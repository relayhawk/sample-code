# Twilio Conversation Relay — Scheduling Bot Sample

A minimal FastAPI server that wires a Twilio phone number to OpenAI chat completions via **Conversation Relay**. Twilio handles ASR and TTS; your server only exchanges JSON text frames over WebSocket.

The bot collects a caller's name, phone number, and desired meeting time, then confirms and ends the call.

---

## How it works

1. Twilio calls your `/incoming-call` webhook (HTTP POST).
2. The server responds with TwiML that plays a recording disclosure and hands the caller to `<ConversationRelay>` pointed at `/relay-ws`.
3. Twilio opens a WebSocket to `/relay-ws` and sends `prompt` messages (transcribed speech).
4. The server forwards each prompt to OpenAI chat completions and sends the reply back as a `text` message for Twilio's TTS.
5. Once the model has all three fields (name, phone, time), it calls the `book_meeting` tool. The server speaks the confirmation and sends `{"type":"end"}` to close the session.

## Quick start

### 1. Clone and configure

```bash
cd twilio-conversation-relay
cp .env-example .env
```

Fill in `.env`:

| Variable | Description |
|---|---|
| `OPENAI_API_KEY` | Your OpenAI API key |
| `OPENAI_MODEL` | Model to use (default: `gpt-5-mini`; fallbacks: `gpt-4.1-mini`, `gpt-4o-mini`) |
| `TWILIO_AUTH_TOKEN` | From your Twilio console |
| `NGROK_AUTHTOKEN` | From your ngrok dashboard |
| `NGROK_URL` | (Optional) Static ngrok domain, e.g. `your-domain.ngrok-free.app` |

### 2. Start the server

```bash
docker-compose up --build
```

- FastAPI runs on port **5002** (ngrok dashboard on **4041** to avoid conflicting with the `twilio-openai` sample on 4040).
- Watch logs for `Application startup complete` and the ngrok public URL.

### 3. Wire up your Twilio number

In the [Twilio Console](https://console.twilio.com/):

1. Go to **Phone Numbers → Manage → Active Numbers** and select your number.
2. Under **Voice Configuration → A call comes in**, set:
   - **Webhook**: `https://<your-ngrok-host>/incoming-call`
   - **HTTP Method**: `POST`
3. Save.

### 4. Call the number

Expected experience:

1. "This call is being recorded for quality and training purposes."
2. "Hi! I can help schedule a meeting. To get started, could I get your name and phone number?"
3. Provide name and phone → bot acknowledges and asks for a meeting time.
4. Provide a time → bot says "Thanks {name}, we'll reach you at {number} at {time}." Call ends.

## Model fallbacks

If `gpt-5-mini` is unavailable on your account, set `OPENAI_MODEL` in `.env`:

```
OPENAI_MODEL=gpt-4.1-mini
# or
OPENAI_MODEL=gpt-4o-mini
```

---

## What's out of scope

- No actual call recording (only the disclosure message).
- No calendar integration — the confirmation is purely spoken.
- No token streaming — one completion per turn keeps the code minimal.

---

## Generated TwiML

When Twilio hits `/incoming-call`, the server responds with this TwiML (generated by `relay_app/services/twilio_service.py`):

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Response>
  <Say>This call is being recorded for quality and training purposes.</Say>
  <Connect>
    <ConversationRelay url="wss://&lt;your-ngrok-host&gt;/relay-ws" welcomeGreeting="Hi! I can help schedule a meeting. To get started, could I get your name and phone number?" />
  </Connect>
</Response>
```

- `<Say>` plays the recording disclosure before anything else.
- `<ConversationRelay>` hands the call to Twilio's built-in ASR + TTS engine, which opens a WebSocket to your server's `/relay-ws` endpoint and handles all audio I/O — your server only ever sees and sends JSON text.
